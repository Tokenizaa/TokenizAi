# ADR-009: Persistência PostgreSQL + Drizzle + Migrações por Módulo

## Status
Proposed

## Contexto
O estado atual persiste em arquivo JSON em `/tmp/nettoscorp-tokenizai-db.json` (`server.ts`, `loadDatabase`/`persistDatabase`). Não há banco relacional conectado no TokenizAo (apesar de `@nettoscorp/db` definir schema Drizzle de 13 tabelas e migration SQL). Não há versionamento de schema por módulo, nem estratégia de migração. Isso impede produção (dados voláteis, sem transações, sem RLS, sem backup).

## Decisão
Adotar **PostgreSQL + Drizzle ORM** como fonte operacional durável (alinhado ao ADR-002), com:

- `@nettoscorp/db` como pacote de schema base e utilitários Postgres (já existe, Fase 1).
- **Uma migration por módulo** em `modules/<id>/migrations/`, versionada (`YYYYMMDDHHMMSS_nome.sql`), aplicada em ordem topológica de dependências pelo `ModuleLoader`/`createApp`.
- Drizzle Kit para gerar migrations a partir do schema TS; suporte a SQL bruto (`ModuleMigration.sql`) para Supabase.
- Drift detection entre schema TS e migrations aplicadas (fail no build se houver divergência não revisada).
- RLS nativo por tenant (ADR-007) aplicado nas tabelas de cada módulo.

### Alternativas consideradas
| Opção | Prós | Contras |
|-------|------|---------|
| A. PostgreSQL + Drizzle + migrations por módulo (escolhido) | Transações, RLS, versionamento, ecossistema Supabase já usado | Requer provisionar/ligar PostgreSQL; migrations precisam de ordem de dependência |
| B. Manter JSON em arquivo (status quo) | Zero infra, simples | Não é produção: sem transações, sem RLS, sem backup, dados voláteis |
| C. Outro banco NoSQL | Escrever fácil | Sem transações ACID, sem RLS nativo, fora do padrão Supabase da empresa |

## Consequências
### Positivas
- ✅ Dados duráveis, transacionais e com backup
- ✅ RLS multi-tenant no banco (ADR-007)
- ✅ Schema versionado e auditado por módulo

### Negativas / Trade-offs
- ⚠️ Dependência de PostgreSQL disponível em dev/prod (mitigar: Docker Compose local, Supabase em homologação/produção)
- ⚠️ Migrações por módulo exigem coordenação de ordem (resolvido pelo loader topológico)
- ⚠️ Dados existentes em JSON precisam de script de migração one-off
